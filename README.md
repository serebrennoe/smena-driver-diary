# Смена

Мобильное веб-приложение для дневника смен водителя. Тестовое задание arqa: https://jobs.arqa.cc/.

## Что работает

- Сводка за выбранный день: поездки, выручка, комиссия, на руки, наличные и карта.
- Переключение дней недели, соседних дней и выбор любой даты в календаре.
- Добавление поездки, валидация полей на клиенте и сервере, детали поездки.
- Серверное хранение в Cloudflare D1 (SQLite), данные сохраняются после перезагрузки.
- Защита от повторной отправки по ID и содержимому поездки, в том числе при конкурентных запросах.
- Мобильный интерфейс, адаптация под компьютер, состояния загрузки, пустого дня, ошибки и успешного сохранения.
- Manifest и иконки для добавления на домашний экран. Требуется интернет; это веб-приложение, не APK/IPA, service worker и офлайн-режим не реализованы.

Начальный экран открыт на 8 октября 2026 года с явно обозначенными демонстрационными данными. Исходный пример работодателя доступен за **1 октября 2026 года**: 2 поездки, выручка 3 900 ₸, комиссия 585 ₸, на руки 3 315 ₸. Есть дополнительные примеры за 7 и 8 октября. Все они находятся в `data/trips.json`, загружаются на сервере идемпотентно после применения миграции и не подменяют сетевой ответ на клиенте.

## Стек

React 19, TypeScript, Vinext/Vite, Cloudflare Workers, D1/SQLite, Drizzle для миграций. Иконки Lucide, шрифт Manrope (SIL Open Font License). Доменные функции не зависят от фреймворка. Интерфейс вдохновлён Uber, inDrive и Careem; код, композиция и бренд самостоятельные.

## Запуск локально

Требуется Node.js 24 LTS и pnpm 11.25.0. Без облачных ключей и авторизации Cloudflare.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm db:local
pnpm dev
```

Открыть адрес, который напечатает сервер. `db:local` применяет миграции к локальному эмулятору D1 и записывает применённые файлы в служебную таблицу, поэтому его можно запускать повторно. Данные находятся в `.wrangler/state`, которая исключена из Git. После изменения схемы: `pnpm db:generate`, `pnpm build`, `pnpm db:local`.

Для просмотра готовой сборки вместо `pnpm dev`: `pnpm start`. Настройка Sites нужна только для облачной публикации, локальный запуск работает без неё.


13 тестов на `node:test`: точная сводка из задания, пустой день, дробные суммы, валидация, комиссия 0%/100%, повтор по ID, повтор с другим ID, 16 конкурентных запросов, конфликт ID, эквивалентные временные зоны, переход через полночь, некорректные календарные даты и SQL-фильтрация по дню. Интеграционные тесты используют настоящий SQLite и SQL-миграцию приложения, а не mock-проверку уникальности. Эмуляция адаптера повторяет только методы D1 `prepare/bind/run/first`.

## API

### GET /api/trips?date=2026-10-01

Возвращает `date`, `timezone: Asia/Almaty`, `currency: KZT`, `trips` и `summary`. Поездки упорядочены по времени начала, сначала новые. Пустой день: пустой массив и нулевая сводка. Некорректная дата: 400.

### GET /api/summary?date=2026-10-01

```json
{"date":"2026-10-01","timezone":"Asia/Almaty","currency":"KZT","count":2,"revenue":3900,"commission":585,"net":3315,"cash":1500,"card":2400,"duration":37,"cashCount":1,"cardCount":1}
```

### POST /api/trips

Content-Type: application/json

```json
{"id":"my-trip-001","start":"2026-10-08T16:00:00+05:00","end":"2026-10-08T16:25:00+05:00","amount":2500,"payment":"card","commission":375}
```

- `id` необязателен; рекомендуется генерировать один ID на операцию и повторять его при сетевых ошибках. Интерфейс делает именно так.
- Дата и время обязательны в ISO 8601 с `Z` или смещением. Окончание строго позже начала.
- Сумма больше 0, комиссия от 0 до суммы. Числа до 1 млрд тенге, не более двух знаков после запятой. Строки вместо чисел не принимаются.
- Оплата только `cash` или `card`.
- 201: `{trip, duplicate:false, day}`; 200 при повторе: `{trip, duplicate:true, day}`.
- 400: невалидные данные и ошибки отдельных полей; 409: тот же ID с изменённым содержимым; 413: большой запрос; 415: неверный Content-Type; 503: база недоступна.
- Изменения данных с другого browser origin отклоняются; curl без Origin разрешён для проверки API.

## Расчёты и повторы

День определяется по **началу поездки** в UTC+5 (Астана/Алматы); поездка через полночь целиком относится к дню начала. Значения API в тенге, в базе и во время сложения используются целые тиыны. `net = revenue - commission`. Наличные и карта показывают выручку до комиссии. `duration` выражена в минутах.

Первичный ключ `id` и уникальный индекс `fingerprint` защищают запись в самой базе. Fingerprint: SHA-256 от нормализованных UTC начала/окончания, суммы/комиссии в тиынах и способа оплаты. Одинаковые данные с другим ID или другим эквивалентным смещением времени также не дублируются. `INSERT ... ON CONFLICT DO NOTHING` атомарен. После него сервер читает сохранённую запись и проверяет конфликт ID; предварительная проверка существования не используется как гарантия уникальности.

Уточнение: две действительно разные поездки с полностью одинаковыми временем, суммами и оплатой будут считаться дублем. Для реального агрегатора вместо такого fallback стоит использовать стабильный внешний ID поездки.

## Структура

- `app/page.tsx`, `app/globals.css`: интерфейс и состояния.
- `app/api/trips/route.ts`, `app/api/summary/route.ts`: HTTP API.
- `lib/trips.ts`: валидация, нормализация, денежные расчёты.
- `lib/trip-service.ts`: атомарное сохранение и дедупликация.
- `db/schema.ts`, `drizzle/`: схема и версионированные миграции.
- `data/trips.json`: пример задания и демонстрационные поездки.
- `tests/trips.test.mjs`: модульные и SQLite-интеграционные тесты.

## Границы решения

Один демонстрационный дневник, без собственных аккаунтов, биллинга и реальных платёжных интеграций. Развёрнутая версия Sites изначально закрыта настройкой доступа платформы. API предназначен для небольшого тестового набора: пагинация, rate limiting и многопользовательская изоляция не входят в это задание. Для публичного production-сервиса они потребуются. Переключение дат и суммы не рассчитываются из моков в браузере: источником истины остаётся сервер.
